# String keys and the i18n runtime (LOC-0007, LOC-0010)

For developers and writers. Runtime: `src/i18n` (decision D-0006). Tables: `src/i18n/strings/<lang>.json`
(flat `key → ICU message`), layout/context metadata: `src/i18n/strings/en.meta.json`.

## Using it
```ts
import { t, tSource } from '../i18n';
import { formatClock, formatNumber } from '../i18n/format';

g.text(t('ui.results.title'), …);                                   // plain
g.text(t('ui.results.subtitle', { title, patient }), …);           // placeholders
g.text(t('hud.chain_combo', { combo }), …);                         // "chain ×{combo, number}"
g.text(formatClock(op.timeLeft), …);                                // locale m:ss
g.text(tSource(op.lostReason), …);                                  // simulation text (see below)
```
- Never concatenate translated fragments (`t('a') + ' ' + t('b')`) or build sentences with template
  literals — add one message with placeholders so each language can reorder. `npm run i18n:check` fails
  on English literals or template literals passed to `g.text`, `g.textBlock`, `giltText`, `button` or
  `op.popup` in `src/scenes` and `src/ui`.
- Numbers go through ICU `{n, number}` or `formatNumber`; counts through `plural`:
  `"{n, plural, one {# stitch} other {# stitches}}"` (Polish needs one/few/many/other — translators add them).
- Every new key needs an `en.meta.json` entry (`scene`, `font`, `size`, `maxPx`, `context`, optional
  `maxLines`, `charLimit`, `note`, `dnt`) — `npm run i18n:validate` enforces it, and the width check uses it.
- Keys are never reused for a different meaning; changing the English meaning means a new key.

## Key namespaces
| Pattern | Use | Example |
|---|---|---|
| `ui.<screen>.<name>` | Menus, screens, buttons | `ui.title.new_game`, `ui.options.language` |
| `ui.common.*` | Shared words (Back, On, Off) | `ui.common.back` |
| `hud.*` | Operation HUD, pause menu | `hud.vitals`, `hud.pause.resume` |
| `tool.<id>.name` / `tool.<id>.hint` | Instruments (`id` = `ToolId`) | `tool.leech.name` |
| `rating.<r>` | Action grades (`cool/good/bad/miss`) | `rating.cool` |
| `rank.<r>` | *Not used:* rank letters XS/S/A/B/C are never translated (below) | — |
| `label.<entity>.<event>` | Caption above a rating popup | `label.barb.freed` |
| `popup.*` | Floating popups | `popup.litany`, `popup.vitals_loss` |
| `loss.*` | Loss reasons | `loss.timeout` |

## Speakable and story lines share one id (VO, subtitles and text)
Story and operation content stays in English inside `src/content` and is addressed by stable ids
generated by `src/i18n/extract.ts` — the same ids AUD uses for VO files and subtitles:
| Id | Meaning |
|---|---|
| `<storyId>.<NNN>` | Story line NNN (1-based, 3 digits), e.g. `s1-2.014` |
| `<storyId>.place`, `<storyId>.<NNN>.as` | Scene caption; speaker-name override |
| `<opId>.title` / `.patient` / `.diagnosis` | Operation chart |
| `<opId>.p<phase>.<n>` | Assistant callout *n* when phase *phase* (0-based) starts, e.g. `op1-2.p0.1` |
| `bark.<flag>` | One-shot bark (`sayOnce` flag), e.g. `bark.flooded`, `bark.low-vitals` |
| `bark.<file>.<slug>` | Other simulation barks |
| `chapter.<id>.title`, `char.<id>.name` / `.title` | Chapter titles, cast |
Inserting a line renumbers the later lines of that scene: after the NAR script lock, add lines only at
the end or coordinate the renumbering with AUD and LOC.

## Simulation text (until LOC-0011 lands)
The DOM-free simulation (`src/surgery`, GAM-owned) still emits English rating labels, popups and loss
reasons. The HUD passes them through `tSource(text)`, which maps the English text to its
`label.*`/`popup.*`/`loss.*` key (and reformats `-12`/`+25` vitals popups). `npm run i18n:check` and
`tests/i18n.test.ts` fail if the simulation gains a label, popup or loss reason with no key. Callouts and
barks are content (English at runtime, exported with the ids above).

## Rank letters (LOC-0010)
**XS, S, A, B, C stay Latin capitals in every language**, including RU/ZH/JA/KO — they are symbols on
the wax seal, not words. Translator note in the termbase (`XS` row, `dnt=yes`). Rating words follow the
OPS wording decision (D-0008) and the termbase (LOC-0037).

## Tools
| Command | What it does |
|---|---|
| `npm run i18n:check` | Key scanner: missing / unused / non-literal keys, hard-coded draw text, un-keyed simulation text |
| `npm run i18n:validate` | Locale files: JSON, ICU syntax, placeholder parity, whitespace, untranslated keys (`@fallback` to allow), termbase |
| `npm run i18n:glyphs [-- --emit]` | Glyph coverage per locale × font role; glyph lists for font baking (`loc/glyphs/`) |
| `npm run i18n:widths` | Pixel width budgets from the font files (`en.meta.json` `maxPx`, `maxLines`, tray width) |
| `npm run i18n:pseudo` | Writes `loc/pseudo/qps*.json` (the game generates them itself: `?lang=qps`, `qps-long`, `qps-cjk`) |
| `npm run i18n:export [-- --lang de]` | XLIFF 1.2 export: `loc/export/ui.<lang>.xliff`, `content.<lang>.xliff` |
| `npm run i18n:import -- <file.xliff>` | Imports translated XLIFF into `src/i18n/strings/<lang>.json` / `loc/content/<lang>.json` |
| `npm run i18n:wordcount [-- --baseline]` | Word counts per chapter × scope, new/changed since the last handoff |
All checks also run in `npx vitest run` (`tests/i18n.test.ts`, `tests/i18n.scripts.test.ts`).
